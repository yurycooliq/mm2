# mm2 trusted desktop controller

Verify native run model=settings gpt-6-astra, reasoning=max (or the trusted
explicit stronger reasoning policy). Never silently switch models. Read trusted
read-only policy and the live server registry; do not run a copied SQLite DB as
a second controller. Untrusted workers cannot access this DB or broker credentials.

Recover DISPATCHING/UNKNOWN effects by exact stable marker and remote body hash,
including closed issues. A missing search/list result never permits a blind POST.
If reconciliation is unresolved, retain WAITING_ACCESS/OWNER. Claim only current
policy jobs with transactional leases/generation; overlap triggers coalesce.
Renew leases and verify the ticket immediately before each broker effect.

Give each role only verified sanitized inputs and required capabilities. The
initial deployed policy is A0. A1 requires actual sandbox denial checks and an
independent exact-SHA check broker; A2/A3 and funded authority are not enabled by
generated issue text. Codesandbox/workflow/financial gates cannot self-approve.

Persist immutable checkpoints, unsuccessful experiments and trial counts. Only
one coding/review/replay job and one strategy experiment run concurrently.
No new finding means a durable no-change receipt, no duplicate issue, no routine
notification. Notify meaningful findings, completion, failures or necessary
owner action. Detailed daily reports only on explicit request. Secondary cleanup
uses exact verified manifests with current pins/leases, never financial expiry
or primary journals.

Inspect status.service_health even when the job queue is empty. The allowlisted
status is HEALTHY, RUNNING, FAILED or UNAVAILABLE, with safe reason/state/result/
exit fields, UTC start/exit metadata and fingerprint. An inactive oneshot whose
last result is success and exit status is 0 is healthy. Fingerprints exclude
timestamps; notify only a new actionable failure signature, a materially changed
UNAVAILABLE condition or recovery, and stay quiet while unchanged. This signal
grants no restart, raw-log/environment access or trading authority.

Frozen bundle transport uses files[member]=list[str] base64 chunks, bounded to
96 KiB raw /128 KiB ASCII each. MAX_RECORD is unchanged. The desktop broker must
verify frozen manifest SHA, bounded chunk counts, exact member bytes and decoded
total <=4 MiB before saving, then verify each member hash and the full immutable
bundle. Chunk framing is transport only; it cannot change the claimed input set,
financial evidence class or completeness.
