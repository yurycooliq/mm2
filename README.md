# mm2 · mo-money-2

Rust-движок для одного владельца и одного торгового счёта, детерминированный эмулятор и отдельная панель управления с Telegram-ботом и Mini App. Локальный пакет собирается без AWS. При запуске можно выбрать **симуляцию, торговлю или обе одновременно**; все режимы начинают на паузе.

Технический торговый адаптер реализован на закреплённом `polymarket_client_sdk_v2 = 0.7.0`. Его проверки используют контролируемую mock-биржу и RPC. Реальные ключи, авторизованная сверка счёта, funded canary, выбранный сервер и доходность этим не проверены. Заготовки `trading` и `both` содержат проверенную публичную связь DepositWallet/управляющего адреса, но закрыты по умолчанию: `owner_authorized = false`; семейство рынков ограничено `btc-updown-5m-`.

## Запуск и выбор режима

PowerShell, Docker Desktop и Compose v2:

```powershell
./scripts/bootstrap.ps1
./scripts/start.ps1 -Mode demo -Build          # полностью локальный эмулятор
./scripts/start.ps1 -Mode simulation -Build    # публичные данные, локальные исполнения
```

На Linux:

```sh
sh scripts/bootstrap.sh
python3 scripts/start.py --mode demo --build
python3 scripts/start.py --mode simulation --build
```

Выбери одну команду запуска. `--build` / `-Build` нужен при сборке новой версии; для готового проверенного образа его можно опустить. Если Python отсутствует в PATH, `start.ps1` принимает `-PythonPath`. Предварительный просмотр не запускает сервисы и не читает секреты:

```sh
python3 scripts/start.py --mode both --dry-run
```

| Выбор | Конфигурация | Поведение |
| --- | --- | --- |
| `demo` | `config/demo.toml` | Синтетическая биржа и данные без подключения к Polymarket. Внутренний режим — `emulator`. |
| `simulation` | `config/simulation.toml` | Публичные наблюдения рынка и локальная модель заявок/очереди. Реальных ордеров нет. |
| `shadow` | `config/public.toml` | Публичные данные и неотправленные предложения без моделирования исполнений. |
| `trading` | `config/trading.toml` | Один реальный счёт через ограниченный V2-адаптер после прохождения его проверок. |
| `both` | `config/both.toml` | Торговая и независимая симуляционная линии получают общие наблюдения; деньги и журналы разделены. |

Wrapper выбирает конфигурацию только в окружении запуска и выполняет `docker compose config --quiet` перед `up`. Существующий `.env` сохраняется. Прямой `docker compose up` без выбора профиля по-прежнему использует demo. Нативный бинарник поддерживает `--config`, явный `--mode` и `--check`; последний проверяет форму конфигурации, а не доступность счёта или биржи.

Панель: **http://127.0.0.1:8080**. Двигатель: **http://127.0.0.1:8088/healthz**. Для входа нужен `MM2_CONSOLE_TOKEN` из приватного `.env`. Внутренний `MM2_ENGINE_API_TOKEN` браузеру не передаётся. Bootstrap создаёт независимые случайные ключи, не выводит их и не заменяет существующий файл.

Resume отдельно разрешает работу выбранного режима. Pause прекращает новые предложения и запрашивает отмены. Kill сохраняет запрет после перезапуска; Reset возвращает на паузу и не пополняет капитал. Отправленная отмена не освобождает резерв до авторитетного подтверждения. Команды имеют ID и ожидаемую версию; при неизвестном исходе повторяется исходный запрос с тем же ID. В торговом режиме Resume дополнительно требует свежей сверки счёта, пользовательского потока и heartbeat.

| `crates/mm2-strategy` | Детерминированные BUY-only правила, пары котировок, хедж дисбаланса, свежесть и ограниченные сигналы. |
| `crates/mm2-portfolio` | Общий конечный капитал, позиции по рынкам, комиссии, резервы, receipt-учёт merge/расчёта и лимиты риска. |
| `crates/mm2-live` | V2 исполнение и отдельный Polygon closeout: подпись, размещение/отмена, сверка, heartbeat, merge/redemption и durable account ledger. |
| `crates/mm2-engine` | Проверенные потоки, выбор режима, стратегия, paper-портфель, журналы, восстановление и минимальный API. |
| `apps/console` | Отдельный процесс: один сборщик статистики, SQLite, авторизация владельца, HTTP и Telegram. |

| `tools/data` | Ограниченный импорт Pendulumflow V3 с контрольными суммами и происхождением данных. |
| `tools/reference` | TypeScript-эталон исполнения и проверка качества архивной книги. |
| `tools/latency` | Read-only измерения CLOB/Binance и сравнение одинаковых событий между хостами. |

## Исполнение, рынки и ограничения

В эмуляции цены и акции используют целые единицы 1e6, произведения цены и количества — точные 1e-12 USD. Новый рынок не получает прежние токены и не начинает с новым капиталом. Paper-портфель сохраняет старые позиции по идентификатору рынка; перед переходом закрывает возможные исполнения. Полные пары объединяются явно синтетически. В demo возможен отдельно обозначенный синтетический расчёт; публичная симуляция сохраняет неразрешённые остатки без выдуманной цены погашения.

В торговле подписанный intent сохраняется до отправки. Неизвестные ответы удерживают резервы; отсутствия заявки в списке открытых недостаточно для её закрытия. Сверка использует авторитетную информацию по известному ID и накопленному исполнению. Замена ожидает подтверждённого завершения прежней заявки. Отключение потока или устаревшая сверка прекращают новые размещения.

Поддерживаемая торговая область — Polygon CLOB V2, BUY-only Up/Down token orders, EOA/canonical proxy/one-owner Safe и закреплённый native-beacon DepositWallet с `signature_type = 3`. Для DepositWallet CLOB использует ERC7739/TypedDataSign-подпись владельца; закрытие стандартных позиций идёт через отдельный gasless relayer. **V3 positions, negative-risk markets и продажи не реализованы.** Тип кошелька, контрактная идентичность, актуальные разрешения и API проверяются перед funded canary.

Публичный счёт в заготовках — `0x04Ad8Cb08F04b58fbcEa273603d6cd151Ba8aDB4`, его управляющий owner/signing address — `0xa2300f310b59df6d0dec94576776ce5435bd0b3f`. Это не подтверждает наличие приватного ключа или права запуска. Две обнаруженные CTF-approval для внешних AutoRedeemer блокируют Resume и подготовку closeout: они могут погашать позиции без изменения nonce кошелька. Владелец должен отдельно отключить их либо дождаться реализации проверенного импорта внешних исполнений. Бот не изменял разрешения и не проводил funded canary.

Relayer API key создаётся владельцем в Polymarket Settings → API Keys → Relayer API Keys и хранится только в приватном окружении, отдельно от CLOB L2 credentials. Для gasless closeout сохраняются подписанный Batch и признак отправки до единственного POST. Batch hash и реальный blockchain transaction hash различаются. Неизвестный ответ не вызывает новую подпись или повтор POST; успех требует финализированного canonical receipt и точных событий. Истечение подписи подтверждается отдельно, не создаёт деньги и требует проверки/Reset. Native POL нужен только прямому транспорту типов 0/1/2; type 3 оплачивает relayer. Детали и внешние acceptance gates: [LIVE_GATEWAY.md](docs/LIVE_GATEWAY.md), [AWS_DEPLOY.md](docs/AWS_DEPLOY.md), [официальная схема авторизации](https://docs.polymarket.com/trading/wallets-auth).

Стратегия по умолчанию использует наблюдаемую книгу. Исследовательская реконструкция с дополнительными сигналами требует их наличия и свежести; Binance spot не заменяет governing TWAP60. Архив Pendulumflow пока не получил экономическую пригодность для holdout. Локальные mock-тесты, синтетические исполнения и быстрый decision loop не доказывают прибыльность.

## Производительность и восстановление

Точный журнал исполнения — первичная зависимость. Его запись и `fsync` предшествуют принятию нового состояния/внешнему эффекту. Сегменты сохраняют общую hash chain; при повреждении или неполной записи запуск отклоняется. Recovery читает execution-транзакции ограниченными порциями вместо накопления полного tape в памяти. Журнал не используется как вторичная статистическая БД.

По умолчанию активный сегмент — **8 MiB**, общий retained-бюджет — **128 MiB**. Отдельно ограничены количество архивов, owner receipts и execution operations; live ledger и portfolio также имеют конечные квоты. Ротация сохраняет всю историю. Заполнение бюджета останавливает дальнейшую работу и требует проверенного backup/обслуживания, а не удаления доказательств. Обычный перезапуск сохраняет IDs, резервы, kill и капитал, начинает на паузе и требует сверки. Fencing действует только на общем локальном файловом пространстве.

Панель использует отдельный Docker-процесс и SQLite. Один сборщик читает готовый snapshot примерно раз в секунду независимо от вкладок. Двигатель не ждёт Telegram, SQLite или браузер. Периодическое форматирование и процентили выполняет worker с одной доступной задачей; пропуски учитываются. Копирование, CPU contention и надёжная запись имеют ненулевую стоимость. Decision timing, API responsiveness и биржевой post/cancel latency — разные измерения.

Оба контейнера работают без root, с read-only корнем, отдельными постоянными томами, ограничениями CPU/памяти и приватными портами. Остановка console не должна останавливать engine. При `both` состояния trading и paper разделены. Профили `trading` и `both` используют общий `live_state_dir = "/data/account-live"`: выбор профиля сохраняет торговые резервы, spend/loss history и общую файловую блокировку счёта. Не переноси тот же счёт в новый каталог для обхода его истории или лимитов.

## Проверки и эксплуатация

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo run --locked -p mm2-emulator -- fixtures/execution/shared-queue.json
python -B -m unittest discover -s scripts -p 'test_*.py'
node --experimental-transform-types --test crates/mm2-strategy/tests/parity.test.ts
```

После сборки обоих Docker-образов:

```sh
python -B scripts/verify_stack.py
```

Container smoke использует собственные помеченные ресурсы и проверяет HTTP-команды, отключение панели, исполнения, fencing и восстановление. Он не торгует финансируемым счётом. Скрипты `ledger_ops.py` и `soak.py` готовят проверку backup/restore и длительный read-only мониторинг; добавление скрипта не означает состоявшийся суточный прогон сервера. Актуальные результаты и ограничения проверок — в [VALIDATION.md](docs/VALIDATION.md).

## Telegram и выбранный сервер

Telegram выключен при пустых настройках. Для `@mm2b_bot` подготовлен [скрытый ввод токена и ключа кошелька](docs/TELEGRAM_SETUP.md) через проверенный SSH/SSM на сервер. При настройке бота Mini App автоматически проверяет подписанный Telegram ID владельца; ручной вход по console token отключается, посторонние получают 404. `/stats` показывает статистику и график стоимости депозита за 24 часа, `/active` — позиции и ордера. Уведомления об исполнениях отправляются только владельцу из вторичных снимков; журнал движка остаётся источником исполнения. Подробности и ограничения в [CONSOLE.md](docs/CONSOLE.md).

Пауза симуляции развёрнута в AWS `eu-west-1` (Ирландия), HTTPS доступен на `mm2.vstage.site`. Проверка geoblock с выбранного IP вернула `blocked=true`: готовность к реальной торговле не подтверждена. Telegram-проверка на устройстве владельца, полные post/cancel tails и остальные funded gates остаются отдельными этапами. Режим и сохранение ключей сами по себе не разрешают реальные ордера.
