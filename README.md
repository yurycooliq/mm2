# mm2 · mo-money-2

Отдельный Rust-движок, детерминированный эмулятор биржи и минимальная панель владельца с Telegram-ботом и Mini App. AWS для локальной работы не нужен.

По умолчанию двигатель запускается **на паузе с эмулятором**. Его сделки, остатки и очередь синтетические. Публичный профиль только читает рыночные данные и создаёт неотправленные предложения. Реальные ордера, ключи кошелька, доходность и доступ к точному TWAP60 здесь не подразумеваются.

## Запуск

Из корня репозитория в PowerShell, с Docker Desktop и Compose v2:

```powershell
./scripts/bootstrap.ps1
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

На Linux:

```sh
sh scripts/bootstrap.sh
docker compose config --quiet
docker compose up -d --build
```

Панель: **http://127.0.0.1:8080**. Двигатель: **http://127.0.0.1:8088/healthz**. Для входа в панель используй значение `MM2_CONSOLE_TOKEN` из приватного `.env`. Это отдельный ключ; внутренний `MM2_ENGINE_API_TOKEN` браузеру не передаётся. Bootstrap создаёт оба ключа случайно, не выводит их и не заменяет существующий файл.

В панели нажми Resume для эмуляции. Pause прекращает новые предложения и запрашивает отмены. Kill сохраняет запрет после перезапуска; Reset возвращает на паузу, Resume остаётся отдельной командой. Запрос отмены не освобождает средства до подтверждения. Команды имеют ID и ожидаемую версию; при неизвестном исходе повторяется исходный запрос с тем же ID.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| `crates/mm2-core` | Фиксированные целые единицы, риск, заявки, резервы, частичные исполнения и неизвестные исходы. Без сети, БД и UI. |
| `crates/mm2-emulator` | Виртуальная биржа: задержки размещения/отмены/уведомления, очередь, post-only, 429, обрывы и воспроизводимые ленты событий. |
| `crates/mm2-engine` | Один владелец состояния, проверка потоков, стратегия для тестов, журнал, восстановление и минимальный API. |
| `apps/console` | Отдельный процесс: один сборщик статистики, SQLite, авторизация владельца, HTTP-панель и Telegram. |
| `apps/dashboard` | React/Vite Mini App: состояние, симулированные остатки, заявки, лимиты, команды, история и логи. |
| `tools/data` | Ограниченный импорт готового архива Pendulumflow V3 с контрольными суммами и происхождением данных. |
| `tools/reference` | Внешний для движка TypeScript-эталон и проверка качества архивной книги. |
| `tools/latency` | Ограниченные read-only измерения CLOB/Binance и сравнение одинаковых событий между хостами. |

## Производительность и журнал

Торговый журнал и вторичная статистика разделены. Точный журнал сохраняет принятые команды и входы переходов эмулятора с проверкой хешей; подтверждение следует за `fsync`. Это осознанная граница надёжности, её задержка относится к исполнению.

Панель использует свою БД и отдельный Docker-процесс. Один сборщик читает готовый снимок примерно раз в секунду независимо от числа вкладок. Движок не ждёт Telegram, SQLite или браузер. Периодические снимки публикуются с ограниченной частотой; форматирование и вычисление процентилей выполняет отдельный worker с одной доступной задачей. Устаревшие снимки пропускаются, переполнение учитывается. Стоимость ограниченного копирования состояния измеряется отдельно. Нулевые накладные расходы и задержки реальной биржи не заявляются.

Оба контейнера работают без root, с read-only корнем, отдельными постоянными томами, ограничениями CPU/памяти и приватными портами. Остановка console не должна останавливать engine.

## Эмулятор и проверки

С установленным Rust из `rust-toolchain.toml`:

```sh
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo run --locked -p mm2-emulator -- fixtures/execution/shared-queue.json
cargo run --locked --release -p mm2-core --example bench_core
```

Без Rust на хосте готовый образ также содержит эмулятор:

```sh
docker run --rm --entrypoint mm2-emulator --mount type=bind,source=/absolute/path/mm2/fixtures,target=/fixtures,readonly mm2-engine:local /fixtures/execution/shared-queue.json
```

После сборки обоих образов, Python 3.13:

```sh
python -B scripts/verify_stack.py
node --experimental-transform-types --test tools/reference/execution.test.ts tools/reference/pendulumflow.test.ts
```

Проверка контейнеров создаёт собственные помеченные ресурсы, проверяет реальные HTTP-команды, отключение панели, исполнения, восстановление, fencing и остановку, затем удаляет только свои ресурсы. История Compose остаётся на месте.

Подробности: [модель исполнения](docs/EXECUTION.md), [архитектура](docs/ARCHITECTURE.md), [данные и измерения](docs/DATA_AND_LATENCY.md), [план завершения](docs/ROADMAP.md), [результаты проверки](docs/VALIDATION.md).

## Telegram и публичные потоки

Telegram отключён при пустых настройках. После получения своего bot token и owner ID заполни `MM2_TELEGRAM_BOT_TOKEN`, `MM2_TELEGRAM_OWNER_ID`, `MM2_MINIAPP_URL` и точный HTTPS-origin в `MM2_ALLOWED_ORIGINS`. Пересоздай только console. Сообщения и Mini App доступны одному владельцу; подписанный Telegram `initData` проверяется сервером. Ключи не добавляй в Git и не вставляй в фронтенд. Подробности в [инструкции console](docs/CONSOLE.md).

Для read-only публичного профиля укажи `MM2_ENGINE_CONFIG=./config/public.toml` и пересоздай engine с **новым отдельным томом состояния**. Эмуляторный журнал нельзя подменять публичным режимом. Публичный HTTPS/WSS, TLS, geoblock и готовность обоих исходов проверяются; ошибки оставляют двигатель без предложений. Прямое публичное соединение требует отдельной проверки на выбранном хосте.

## Состояние после перезапуска

Журнал в `engine-data` сохраняет команды, kill, симулированные деньги, позиции и заявки. Перезапуск возвращает на паузу или в killed и выполняет отмену/сверку эмуляторных заявок. Один процесс на общем локальном томе обеспечивается файловой блокировкой. Это не распределённое лидерство между серверами.

Журнал ограничен 8 MiB по умолчанию, максимумом 64 MiB и 10,000 команд. Достижение границы останавливает работу; автоматической ротации с потерей истории нет. Панель хранит ограниченные вторичные выборки и показывает задержки/пропуски. Не удаляй том или `commands.jsonl` для обычного восстановления.

Эмуляторная сессия привязана к одному рыночному контракту. При переходе к новому контракту с сохранёнными позициями требуется остановка; расчёт выплат, продажа, merge/redemption и многорыночная книга позиций ещё не входят в текущий исполнительный контракт. Тестовая стратегия не прошла экономическую проверку и не разрешает реальную торговлю.
