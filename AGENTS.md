# mm2 engineering contract

All repository changes go through pull requests. Use a dedicated `codex/` branch for each logical change, push that branch, and open a PR against the intended base; never push directly to `main`. Keep unfinished work in draft PRs. For stacked PRs, name the prerequisite PRs and merge them in dependency order. Describe the problem, resulting behavior, validation and remaining limitations. Obtain another contributor's review before merging code, satisfy the applicable CI checks, and merge only when authorized for the task. Fetch the current base and recheck the diff before merging. Record the PR URL and exact source/deployed revisions in release handoffs. A PR or passing CI does not authorize funded trading or a server restart. Keep private runtime files, credentials and generated operational evidence out of commits. GitHub branch protection should enforce this workflow when the repository plan supports it; if unavailable, report that limitation and follow the rule without claiming technical enforcement.

Use `main` as the integration baseline and finish ready prerequisites before opening more dependent fixes. Keep at most three open PRs in a dependency stack. Ready PRs target the current `main`; experimental strategy/measurement work carries the `experimental` label and stays Draft until its explicit evidence gates and independent review are accepted. Do not promote default-changing experiments on mechanical tests alone. A separate review agent qualifies as another contributor: record its identity, exact head/base and conclusion; an owner-account COMMENT is an agent receipt, not a human approval. Run `scripts/pr_hygiene.py audit` at task start and `ready --pr NUMBER` before integration. The helper never merges, changes readiness, or deletes anything. A failed/unavailable hosted job is not a passing test: complete equivalent isolated validation and obtain a documented owner exception for the exact revisions if hosted CI cannot start. Preserve ancestry with merge commits when integrating stacked PRs, retarget children before deleting a prerequisite branch, and remove only verified clean, fully integrated worktrees with no needed ignored data. Preserve operational evidence outside their `worktree` subdirectories. See `docs/INTEGRATION_WORKFLOW.md`.

One owner and one funded account. All modes start paused. Direct Compose defaults to offline demo; startup wrappers select simulation, trading, both, shadow or demo. Public simulation is synthetic execution; shadow submits nothing. Trading/both use the gated technical V2 SDK adapter, not permission inferred from research or mode selection. Require the intended eligible owner/account/host and explicit funded authorization before external money-moving requests. No profit claims from mocks, synthetic fills or incomplete historical data.

The deterministic core, strategy and portfolio have no network, UI, wall-clock or database dependencies. Use exact fixed-point quantities and caller-supplied time/evidence. Preserve order/market identity, partial fills, cancel-in-flight reservations and unknown outcomes. Cancel-before-post replacements must not acquire free queue priority. Market rollover preserves one finite capital pool and old market positions. Synthetic merge/demo resolution must remain labeled; public prices are not authoritative settlement receipts.

The engine/live actors own execution and durable command/audit state. In both mode, paper/live accounting and journals stay separate. Trading/both must use the same explicit account ledger/fence; a mode change cannot reset spend/loss history or possible-fill reservations. Sync intents before external effects and retain exact retry identities. Segment rotation preserves the complete chain; stream replay and expose finite journal/receipt/portfolio quotas. Never delete uncertainty or reset capital to recover capacity. The console owns Telegram, HTTP frontend, historical statistics and SQLite. Console polling, downtime and storage must not be required for engine decisions. All queues, histories and ingress must be bounded. Do not claim zero telemetry cost; measure and expose sampling/drop behavior.

Secrets belong only in ignored private runtime files/environment. Never log Telegram initData, bot tokens, API secrets, signing keys or signed wire intents in secondary telemetry. Preserve TLS certificate validation. Pin supported SDK/protocol/deployment/signature identity together. Reject unsupported V3 positions, negative-risk markets and sells. CLOB V2 signature type 3 supports the pinned native-beacon DepositWallet through the SDK's canonical ERC7739/TypedDataSign wrapper; controlling EOA, account wallet and Relayer API credentials remain distinct. Verify factory, effective per-wallet beacon implementation, owner, EIP712 domain and approvals before funded readiness. External AutoRedeemer CTF approvals block Resume/preparation until the owner disables them or a reviewed external-receipt path is implemented; wallet nonce alone cannot detect their effects.

Standard-market closeout uses a separate Polygon worker. Direct EOA/proxy/one-owner Safe persist exact raw transaction bytes/hash/nonce before broadcast and pay finite POL gas. DepositWallet persists its complete owner-signed Batch/body/digest/deadline/prestate, then syncs dispatched=true before one gasless relayer POST. Never automatically repeat that POST or refresh nonce/signature after uncertainty. The batch digest is not an onchain transaction hash. Only a canonical finalized factory batch/signature and wallet event proof plus authenticated token/collateral effects credits returns. Expiry is a distinct canonical proof: finalized timestamp strictly past deadline, unchanged wallet nonce and retained condition tokens. It creates no receipt/cash and leaves execution faulted for investigation/Reset. A failed durable write poisons the writer until checked restart; Reset cannot recover it. No helper changes approvals, creates keys, transfers funds or sends a funded canary implicitly.

Validate with Rust tests/Clippy/format, Python console/data/latency/ops tests, bounded Rust/TypeScript quote parity, dashboard build, real container smoke and browser interaction checks. Backup/restore into new paths and distinguish mocks, synthetic tapes, observed public feeds, authenticated venue evidence and selected-host performance. Keep current counts/results in docs/VALIDATION.md; preserve dated historical reports as dated evidence. Economic holdout, AWS host, HTTPS/Telegram owner acceptance and funded canary remain explicit external gates.
